# Подготовка и проверка рабочего проекта

## Цель

Подготовить структуру из `Codex.md`: инструкции в `directives/`, Python-скрипты в `execution/`, воспроизводимые промежуточные данные в `.tmp/`.

## Входные данные

Корень проекта определяется по расположению скрипта. Ключи API и доступ к облачным сервисам для этой операции не нужны.

## Инструмент и порядок действий

1. Используй существующий `execution/setup_project.py`.
2. Запусти его из корня проекта: `python execution/setup_project.py`.
3. Проверь сообщения `OK` для трёх папок, `.env` и `.gitignore`.
4. Повторный запуск не должен изменять существующие настройки или дублировать строки исключений.

## Результат

Созданы рабочие папки, заготовка `.env` без секретов и правила `.gitignore` для временных данных, учётных данных и кеша Python. Это инфраструктура проекта; пользовательские результаты рабочих задач размещаются в облачных сервисах согласно `Codex.md`.

## Ограничения и особые случаи

- Скрипт не устанавливает зависимости, не выполняет сетевые запросы и не расходует платные ресурсы.
- Существующий `.env` сохраняется. Существующий `.gitignore` дополняется недостающими правилами.
- `.gitignore` предотвращает добавление новых файлов, но не снимает с отслеживания уже закоммиченные файлы.
- Не создавай фиктивные `credentials.json` и `token.json`. Для задач с Google API нужны реальные OAuth-данные и авторизация пользователя. Наличие файлов само по себе не подтверждает работоспособность доступа.
- В прежнем Windows-окружении команда `python` указывала на неработающий псевдоним WindowsApps; там использовался `C:/Users/InfDesign/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe`. На текущем Mac проверена команда `python3`. После очередного переноса снова проверь путь к интерпретатору.
- Для каждой конкретной рабочей задачи сначала прочитай соответствующую инструкцию и проверь существующие скрипты. При ошибке исправь инструмент, проверь его и дополни инструкцию подтверждёнными сведениями.
- После переноса папки с Windows на macOS не используй скопированный `node_modules`: в нём нет нативного `@rolldown/binding-darwin-arm64`, и Vite не запускается. Выполни `npm ci --include=optional` в корне, `vercel-app/`, `vercel-app/participant/` и `integrations/Leed-generation/` по мере работы с этими приложениями. Lock-файлы сохраняются; после установки проверь запуск Vite. В двух дашбордах доступен `npm run check`; в двух приложениях участника такой команды нет, используй `npm run build`.
