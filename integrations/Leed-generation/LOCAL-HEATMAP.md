# Локальная интеграция с UX-Lab

Исходники распакованы из `Leed-generation-main.zip`. Подключение к GitHub не используется.

## Открыть

- Интерфейс с кнопками записи теста: http://127.0.0.1:5175/leads-table?ux_study=leed-local
- Карта: http://127.0.0.1:5173/?screen=results-overview#/heatmap-live?link=leed-local

Из корня рабочего каталога: `python execution/start_local_heatmap.py`.
При первом запуске нужны установленные зависимости: `npm ci` в корне UX-Lab и в `integrations/Leed-generation`.
Скрипт поднимает отсутствующие серверы, синхронизирует общий сборщик, пишет логи в `.tmp/local-heatmap/`.
После изменения Python API его процесс нужно перезапустить. Занятые порты скрипт не освобождает.

## Что подключено

Общий сборщик `public/ux-lab-collector.js` принимает реальные клики мышью/касанием. Адаптер
`src/ux-lab/install.ts` покрывает весь реестр экранов, включая настройки, а также `/` и `/showcase`.
SPA-переходы и перезагрузка сохраняют ID сессии. Новая независимая вкладка создаёт новую сессию.
Параметр `ux_study` задаёт отдельное исследование и запоминается на время вкладки.

## Раунды тестирования

В нижней части сайдбара UX-Lab показаны состояние сбора, последнее сохранённое событие и число сессий текущего исследования. «Обновить» проверяет API и перечитывает данные. После собственного теста нажмите «Зафиксировать раунд» и подтвердите действие. Текущий раунд останется доступен в результатах, его сбор остановится сразу: сервер не добавляет к статистике запоздавшие клики, посещения, снимки и события задания, а незавершённую видеозапись помечает остановленной. Новый раунд получит отдельный `ux_study`, пустую статистику и ссылку на экране «Проверка и запуск»; его сбор тоже выключен до ручного запуска. Перед выдачей ссылки включите сбор нового раунда. Ссылка локальной версии работает только на этом компьютере; удалённым участникам нужна облачная версия.

Проверка без записи в рабочую базу: `PYTHONPATH=execution python3 -m unittest check_multi_study.MultiStudyTests.test_fix_round_preserves_results_and_creates_clean_link`. Проверка сайдбара в браузере: запустите Vite на 5173 и `execution/serve_heatmap.py --db .tmp/round-preview.sqlite3` на 5174, затем `ROUND_TEST_API=http://127.0.0.1:5174 node execution/check_round_sidebar.mjs`. Используйте только временную базу: браузерный сценарий создаёт и фиксирует исследование.

Координаты измеряются до обработчиков React. Сохраняются страница, версия, размер окна,
положение вложенной прокрутки и хеш расположения/содержимого видимых элементов.
С версии `leed-local-v2` отдельно сохраняется статический HTML/CSS-фон в момент клика — только в локальную SQLite.
Скрипты и обработчики удаляются, значения полей очищаются; введённые значения маскируются и в скопированном тексте.
Остальные видимые тексты интерфейса входят в фон. ID элементов событий — технические, без имён клиентов.
Старый `track.js` оставлен как исходник, но отключён от `index.html`: запросов к прежнему внешнему серверу нет.
Сбор включён только на localhost/127.0.0.1; публикация сборки не включает аналитику автоматически.

API: `execution/serve_heatmap.py`, порт 5174, хранилище `.local/heatmap.sqlite3` в корне UX-Lab.
Повторные отправки не удваивают события. Временная недоступность API оставляет очередь в sessionStorage.
Фоны повторно отправляются из очереди IndexedDB; их отсутствие не блокирует отображение координат.
Карта опрашивает API каждые 2 секунды; фон предпросмотра сам не собирает клики.

## Граница этой локальной версии

Новый фон — статическая копия DOM/CSS до выполнения обработчика клика, включая фильтры и модальные окна.
Она отображается в iframe без разрешения на скрипты, с ограничивающим CSP. Тепловой слой рисуется отдельно поверх фона.
В выборе — один пункт на экран. Все клики его состояний суммируются в общей плотности по координатам окна;
для разных размеров окна есть отдельный фильтр, чтобы не смешивать адаптивные раскладки.
Фон выбирается из доставленных снимков: предпочтителен основной экран без перекрывающих панелей.
Если снимка нет, отображается исходный интерфейс с отключённым сбором, а не белая сетка.
Агрегированная карта включает клики в модалках/панелях; их позиции относятся к окну, а фон показывает основной экран.
Для точного разбора такого клика сохраняются исходные события и снимки. Это не сопоставление элементов между состояниями.
ID новых фонов включает размеры окна. Старая очередь с одинаковым HTML и разными размерами подтверждается сервером;
один отклонённый снимок больше не блокирует следующие.
Внешние iframe, видео и содержимое canvas не записываются; это не универсальная запись произвольного сайта.
Клики и DOM-снимки сами по себе не являются видеозаписью. Реальное видео запускается отдельно участником (см. ниже); результаты задач автоматически не оцениваются.
Основное приложение UX-Lab теперь использует только проект Lead Generation и события `leed-local`.
Демонстрационные проекты исключены из приложения; исходные примеры компонентов остаются в Storybook.
Старое рабочее пространство браузера перенесено в `ux-lab-workspace-archive-v1`, клики SQLite сохранены.

## Единое подключение проекта

Открыть дашборд: http://127.0.0.1:5173/ . Интерфейс проекта: http://127.0.0.1:5175/leads-table?ux_study=leed-local .
Сборщик обслуживает `/api/project`: обзор, реальные сессии, посещения, сигналы повторных кликов,
настраиваемую последовательность экранов, сохранённые находки и неизменяемые снимки отчётов.
Отчёт сохраняется через печать браузера в PDF; тепловые карты — PNG и ZIP.
Сессия соответствует вкладке, не уникальному человеку. Видео, если участник его записал, отображается основным плеером;
события и отдельные снимки доступны в сворачиваемом блоке. Из старых снимков видео не восстанавливается.
Посещения до добавления их сбора нельзя восстановить; старые клики остаются доступными.
Приостановка сбора распространяется на открытые вкладки при опросе конфигурации; ранее накопленная очередь отправляется.
Проверка всего подключения на временной SQLite, без изменения рабочих данных: `python execution/check_live_project.py`.

Для других проектов рекомендуемая следующая ступень — устанавливаемый JS SDK с идентификатором проекта,
разрешёнными доменами и HTTPS API. Архив исходников нужен только для доработки самого интерфейса,
а не для последующего сбора событий. Расширение браузера подходит для контролируемых тестов, но требует
установки участниками. Текущий адаптер содержит реестр маршрутов и статических подписей Lead Generation:
он ещё не является универсальным SDK произвольных сайтов. DOM-снимки не воспроизводят сторонние iframe/canvas.

## Видеозапись теста

В интерфейсе Lead Generation: «Начать запись теста» → выбрать вкладку Lead Generation и разрешить захват →
пройти тест → «Завершить запись» → дождаться сохранения → «Посмотреть запись».
В дашборде: «Сессии» → ID сессии → основной видеоплеер с Play/Pause, временной шкалой,
перемоткой, скоростью 0.5–2×, отметками кликов и скачиванием WebM. Несколько запусков в одной вкладке
сохраняются отдельными фрагментами. Старые сессии без видео явно отмечены.

Используются стандартные getDisplayMedia и MediaRecorder: никаких расширений. Разрешение браузера требуется
при каждом новом запуске; без него видео не записывается. Поддерживается настольный Chrome/Edge на localhost
или HTTPS после развёртывания. Текущая интеграция включена только локально.
Видео без звука записывает выбранную поверхность целиком, включая видимые значения полей — маскирование
DOM-снимков на видео не распространяется. Это указано перед запуском. Рекомендуется выбрать именно вкладку приложения.

WebM-фрагменты каждые 2 секунды сохраняются в IndexedDB и передаются в SQLite через `/api/recordings`.
Повторы идемпотентны; доступ к готовому файлу поддерживает HTTP Range для перемотки. Сервер добавляет Duration
в WebM Info, поскольку поток MediaRecorder не содержит конечной длительности. Локальная версия ограничена
30 минутами и 256 MiB на фрагмент; UI останавливает запись до лимита размера. Микрофон не запрашивается.
SPA-переходы запись не прерывают. Полная перезагрузка/закрытие вкладки прекращает захват; при следующем открытии
доставляется сохранённая часть с отметкой о прерывании. Для продолжения нужен новый запуск. Последние секунды
до сохранения очередного фрагмента могут потеряться. Web Locks защищают активные записи других вкладок от завершения.
При паузе исследования активная запись заканчивается, уже накопленная очередь отправляется.

Проверка: `python execution/check_session_video.py`. Временная БД, синтетический движущийся Canvas вместо экрана
пользователя, настоящий MediaRecorder/WebM, отказ в разрешении, сбой сети, восстановление после перезагрузки,
Play/Pause, seek, скорость, отметки событий и byte ranges. Реальный системный диалог проверяется пользователем при старте.

# Экспорт и подписи элементов · 25 сентября 2026

- Только «Сохранить PNG» скачивает интерфейс с текущим тепловым слоем в исходном размере окна. Нажатие на саму карту ничего не скачивает. Учитываются режим «Все / Первый клик», выбранный элемент и видимость слоя.
- «Сохранить все» скачивает ZIP с отдельным PNG для каждого экрана и размера окна. Выбор отдельного элемента сбрасывается только для архива; режим кликов и видимость слоя сохраняются. Разные размеры окон не смешиваются.
- Экспорт выполняется локальным `execution/export_heatmaps.mjs` через установленный Chrome/Playwright. Нужны запущенные UX-Lab, API и Lead Generation. Временные файлы удаляются после формирования ответа; экспорт не создаёт событий клика.
- Статические iframe запрещают скрипты: ожидание `requestAnimationFrame` внутри них зависает. Готовность ресурсов проверяется снаружи с ограниченным ожиданием. Изображения с недоступным фоном не выгружаются как успешный результат.
- Новые события содержат границы элемента и подпись из проверенного списка статических названий (`src/ux-lab/element.ts`). Значения полей и имена клиентов не используются для подписей. Для расширения названий дополняется список в адаптере.
- Старым ID не присваивается выдуманное назначение: в списке нейтральные подписи, при наведении отмечаются места кликов. Для новых записей показываются сохранённые границы; общий фон остаётся представительным снимком экрана.
- Проверки: `node execution/check_heatmap_exports.mjs`, `node execution/check_heatmap_elements.mjs`, `python execution/check_heatmap_api.py`.

## Выбор сессии на тепловой карте

Поле «Сессия участника» переключает общую карту и конкретную сессию. Сессия — посещение в одной вкладке, а не уникальный человек. В списке доступны и посещения без кликов; для них показывается пустое состояние с возможностью вернуть всех участников.

Параметр `#/heatmap?session=<id>` сохраняет выбор при обновлении страницы. «Тепловая карта этой сессии» в истории открывает этот адрес. Старый параметр `participant` относится к истории и сам по себе карту не фильтрует.

API `/api/heatmap` и `/api/heatmap/export` применяют `session` к событиям, счётчикам, выбору фона и PNG/ZIP. «Сохранить все» сохраняет все экраны выбранной сессии, а при общей карте — всех сессий. Проверка `python execution/check_heatmap_sessions.py` использует временную БД и проверяет отсутствие смешения даже при одинаковом layout, первый клик, пустую сессию, ссылки и параметры экспорта.
