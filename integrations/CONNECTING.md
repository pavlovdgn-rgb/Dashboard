# Проверка подключений · 29 сентября 2026

Локальный пилот: [проверка подключений](http://127.0.0.1:5173/?screen=connections).
В настройке исследования есть ссылка «Проверить подключение другого интерфейса».
Запуск всех сервисов: `python execution/start_local_heatmap.py`.
Если `python` указывает на неработающий WindowsApps alias, используйте настоящий Python:
`C:/Users/InfDesign/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe`.

## Сайт

1. Создать подключение: название и адрес страницы. Разрешённый origin определяется из этого адреса.
2. Скопировать один `<script defer src="http://127.0.0.1:5176/sdk.js" data-project="…"></script>` в head сайта.
3. Открыть выданную ссылку с `ux_study`, нажать кнопку, перейти на другой экран.
4. Проверить журнал: посещение, клик с техническим ID, посещение следующего экрана.

Без ссылки участника новая вкладка не собирает события. Выбранное исследование сохраняется
в sessionStorage на время вкладки. Полная перезагрузка сохраняет сессию. Скрипт не зависит
от React; следит за сменой страницы без подмены History API. Сбор можно приостановить в пилоте.
Код подключения относится к подключению сайта; в этом пилоте у него одно тестовое исследование.
Несколько исследований на одно универсальное подключение — следующий этап, текущая модель Lead
Generation с несколькими исследованиями сохраняется отдельно.

Готовый независимый сайт работает на порту 5177. `serve_integration_demo.py` создаёт для него
подключение, готовую HTML-страницу и ссылку в `.tmp/integration-demo/connection.json`.
Исходник — `assets/integration-demo/index.html`; воспроизводится без копирования Lead Generation.

Собираются координаты относительно окна, размеры окна, технические ID и время. Текст,
значения полей, URL с query, HTML-снимки и видео универсальный пилот не отправляет.
`data-ux-page` и `data-ux-target` задают понятные статические ID; без них используется
отпечаток маршрута и тип элемента. `data-ux-private` исключает клики по области.
Внешние iframe и canvas не становятся доступными для DOM-аналитики после установки скрипта.

## Figma

1. Подготовить небольшой прототип с двумя-тремя экранами и работающим переходом.
2. Скопировать ссылку из режима презентации (`https://www.figma.com/proto/…`).
3. Зарегистрировать OAuth-приложение UX-Lab в Figma и скопировать **Client ID**.
4. В настройке приложения → Embed API → Add an embed origin добавить точный origin:
   `http://127.0.0.1:5173`. Если открываете через localhost, его origin добавляется отдельно.
5. В пилоте выбрать «Прототип Figma», вставить ссылку и Client ID, создать подключение.
6. Нажать «Открыть прототип для проверки», выполнить переход и проверить журнал.

Client Secret и персональный access token для этого шага не нужны. Регистрация приложения
сама по себе не отменяет права доступа к прототипу. Без Client ID возможен предпросмотр,
но получение событий не считается проверенным. Приложение показывает отсутствие событий,
запрос входа и запроса пароля отдельно. Проверяются origin сообщения **и** окно iframe.

Документированные события: INITIAL_LOAD, PRESENTED_NODE_CHANGED, NEW_STATE,
MOUSE_PRESS_OR_RELEASE, LOGIN_SCREEN_SHOWN, PASSWORD_SCREEN_SHOWN. Событие мыши сохраняется
под исходным названием: пока не проверены его частота и семантика на реальном прототипе,
его нельзя автоматически объявлять единичным кликом. Координаты сохраняются в исходных
системах координат элемента и прокручиваемого фрейма; это ещё не готовая тепловая карта.

Источник: https://developers.figma.com/docs/embeds/embed-api/

**Живая проверка Figma пока ожидает пользовательскую ссылку и Client ID.** Проверки в браузере
используют явно обозначенные сообщения-образцы и замену iframe; это не доказательство
получения событий с серверов Figma. REST-импорт изображений экранов, тепловая карта и
видеозапись Figma не реализованы в этом пилоте.

## Технические границы и проверки

- `public/ux-lab-collector.js` — общий транспорт и сбор кликов с очередью и подтверждением доставки.
- `public/ux-lab-sdk-bootstrap.js` — самостоятельная установка, проверка подключения и посещения.
- `/sdk.js` отдаёт оба исходника одним ответом. Lead Generation также загружает этот пакет
  со своего API 5174; адаптер снимков, заданий и видео остаётся прежним.
- `execution/serve_integration_pilot.py` — API на 5176; отдельная `.local/integration-pilot.sqlite3`.
- Публичный код разрешает только отправку событий своего подключения с зарегистрированного origin.
  Чтение результатов и управление из origin тестируемого сайта запрещены. Это локальный пилот,
  ещё не многопользовательский сервер с авторизацией и публичным HTTPS-хостингом.
- `execution/check_integration_pilot.py` — отдельная временная база; проверяет независимый сайт,
  повтор после потерянного подтверждения, приватные поля, отсутствие сбора без ссылки,
  SPA/reload, паузу, разные вкладки, изоляцию, Figma-контракт и мобильную компоновку.
- `execution/check_live_project.py` — регрессия текущего проекта, включая реальные действия
  в Lead Generation с перенаправлением записи в тестовую базу.
- Результаты пилота и снимки: `.tmp/integration-pilot/`. Базы текущих исследований не используются
  для автоматических тестов. Перед перезапуском основного API сделан SQLite backup.
