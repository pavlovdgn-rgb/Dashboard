# ResultsOverview

**Размер:** desktop 1920×1080 px — подтверждено пользователем для всех пяти экранов.
**Назначение:** обзор результатов: основные цифры, список сценариев и выбор подробного анализа.
**Статус:** отрисовано и проверено в Figma по общему апруву пользователя. [Открыть экран](https://www.figma.com/design/1LeVoicxDT7Sl8TpMPs4hr/Dashboard?node-id=22-3).
**Основания:** [PRD: обзор результатов](../../prd.md), [sitemap](../sitemap.md), [flow анализа](../flows/results-analysis.mmd). F01, F09–F18, F22–F26; D02–D03, D05, D11.

Первый экран после открытия результатов исследования из Studies. Тепловая карта открывается по отдельному действию пользователя. Ни карта, ни replay не загружаются автоматически в обзор.

## Секции (сверху вниз)

### Header — 64 px, на всю ширину 1920 px

- Слева текстовое рабочее название «UX-Lab» и ссылка «Все исследования» → Studies.
- Название текущего исследования: «Покупка в интернет-магазине».
- Справа имя текущего коллеги. Способ входа и меню аккаунта пока не определяются.
- Глобальный поиск, уведомления и администрирование не добавляются.

### Workspace — 1920×1016 px под Header

Горизонтально: Sidebar 240 px и Main 1680 px. Прокручивается Main; Header и Sidebar остаются доступными. При реализации корневой фрейм сохраняет размер 1920×1080; длинный список уходит в вертикальный скролл.

### Sidebar — 240 px слева, высота 1016 px

- Раздел «Настройка исследования» → StudySetup.
- Группа «Результаты»: «Обзор» (текущий экран), «Тепловая карта», «Воронка», «Участники», «Сигналы затруднений», «Отчёт PDF».
- Запись конкретного участника открывается через выбор участника, без неопределённого общего пункта «Открыть запись».
- Переход сохраняет исследование и применимые фильтры. Если анализу нужен сценарий, а он ещё не выбран, выбор выполняется в целевом представлении; первый сценарий молча не подставляется.

### Main / PageHeading — 76 px

- Main: отступы по 32 px, полезная ширина 1616 px. Между основными секциями 24 px.
- Заголовок «Обзор результатов».
- Подзаголовок: «Сценарии исследования и результаты участников».
- Справа действие «Экспорт в PDF» → Report. Там явно выбираются область данных и состав отчёта; кнопка не означает незаметный экспорт только выделенной строки.

### Main / ContextBar — 48 px

- Фильтр «Устройство»: «Все устройства», «Компьютер», «Мобильное устройство».
- Текст «Режим: задания» из настройки исследования.
- При активном фильтре — «Сбросить фильтры».
- Фильтр устройства применяется одновременно к сводке и таблице; текущая область данных видна при переходе к анализу.
- Здесь нет фильтра страницы/состояния: он нужен для подробного анализа конкретного интерфейса и будет в Heatmaps.

### Main / Summary — 112 px

Три равные области по 528 px с промежутками 16 px:

1. «Сценариев» — 3. Подпись «В исследовании»; количество заданных сценариев не меняется от фильтра устройства.
2. «Участников» — 20. Подпись «Уникальных в текущей выборке».
3. «С неполными данными» — 2 из 20. Действие «Посмотреть участников» → Participants с соответствующей выборкой.

Общего среднего процента успеха по разным сценариям нет: показатели рассматриваются по строкам. Состав этой сводки — предложение на согласование, а не ранее утверждённый набор метрик.

### Main / ScenariosTable — заголовок 26 px и промежуток 12 px, шапка 48 px, строка 88 px

- Заголовок «Сценарии · 3» и пояснение «Выберите сценарий для подробного анализа».
- Колонки общей шириной 1616 px: сценарий 480; начали 150; завершили попытку 210; достигли цели 330; неполные данные 210; действие 236; отдельной колонки выбора нет.
- В названии сценария — текст задания в 1–2 строки. Подписи метрик понятны без знания внутренних событий.
- «Достигли цели»: число, знаменатель и процент; рядом видна база оценки, например «Оценены 18 из 20». Пояснение правила доступно по текстовой ссылке «Как считается».
- «Завершили попытку» и «Достигли цели» — разные колонки. При отсутствии подтверждённой оценки показывается «Нет оценки», а не 0%.
- Выбор строки или действие «Выбрать сценарий» заполняет ScenarioAnalysis ниже, без автоматического перехода на карту.
- Повторные попытки не складываются с уникальными участниками. Окончательное правило выбора попытки — D03; до него макет не утверждает производственную формулу.
- По умолчанию строка не выделена. Для обсуждения активного состояния используется пример с выбранным первым сценарием.

### Main / ScenarioAnalysis — 120 px

- Без выбора: «Выберите сценарий в списке выше»; действия подробного анализа недоступны.
- После выбора: «Выбран сценарий: Найти товар и добавить в корзину» и пять текстовых действий: «Тепловая карта», «Воронка», «Участники и записи», «Сигналы затруднений», «Снять выбор».
- «Тепловая карта» → Heatmaps: выбранный сценарий и устройство сохраняются, страница/состояние выбираются уже там.
- «Воронка» → Funnel с тем же сценарием и устройством.
- «Участники и записи» → Participants → ParticipantDetails → Replay. Пользователь выбирает конкретную запись, случайная сессия не открывается.
- «Сигналы затруднений» → Signals с тем же контекстом; доступны все четыре согласованных типа.
- Возврат из подробного анализа восстанавливает выбранную строку, фильтр устройства и положение списка.

## Empty / loading / error и другие состояния

- **ResultsEmpty:** «Пока нет результатов». Если сценарии настроены, их список остаётся видимым; вместо производных метрик — «Нет данных». Действие «Перейти к запуску» → Launch, где доступна ссылка и проверка подключения. Нулевое число фактически пришедших участников допустимо; нулевой процент успеха при отсутствии наблюдений — нет.
- **FilterEmpty:** «По выбранному устройству нет данных» и «Сбросить фильтры». Исследование и сценарии не исчезают.
- **Loading:** «Загружаем результаты» на месте сводки/таблицы; нет преждевременных нулей и активного выбора ещё не загруженной строки.
- **LoadError:** «Не удалось загрузить результаты», «Повторить». Контекст исследования и фильтры сохраняются.
- **IncompleteData:** количество и пояснение рядом с соответствующей метрикой/строкой; технически неполная запись не считается автоматически неуспехом и не скрывается из количества начавших.
- **Свободное изучение:** режим обозначен явно; вместо списка заданий — область «Свободное изучение» с числом участников и полнотой данных. Количество сценарных заданий показывается как «Не применимо». Карта, участники/записи и сигналы доступны; успех и сценарная воронка без цели не выдумываются.

## Проверка компоновки и границ

- Все секции — предложение структуры low-fi, без задания цветов, иконок, теней или границ.
- При трёх строках расчётная высота Main: отступы 64 + PageHeading 76 + ContextBar 48 + Summary 112 + таблица 350 + ScenarioAnalysis 120 + четыре промежутка по 24 = 866 px; доступно 1016 px. Переносы контента проверяются при отрисовке; длинные списки прокручиваются.
- Сначала общий обзор; переход к тепловой карте выполняется по выбору. PDF доступен из обзора без обязательного просмотра карты или replay.
- На согласование: состав сводки и колонок, отдельная область действий выбранного сценария, размещение навигации.
- Не определены этим макетом: правило повторных попыток и завершения, знаменатели производственных расчётов (D03), сбор событий/хранение, шаблон PDF (D11), дизайн-система.
